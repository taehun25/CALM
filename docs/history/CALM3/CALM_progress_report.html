01 / BACKGROUND

왜 CALM이 필요한가

Reliable QoS는 손실 데이터를 복구하지만, 혼잡한 링크에서는 복구 트래픽 자체가 다음 손실을 만드는 양성 피드백이 될 수 있다. CALM은 “재전송이 증가하는 신호 자체를 브레이크로 사용한다”는 사이토카인 폭풍 억제 아이디어에서 출발했다.

정상 복구

HEARTBEAT로 누락을 발견하고 ACKNACK/NACKFRAG가 요청한 Change 또는 fragment를 다시 보내 ACK 진행을 회복한다.

혼잡 시 문제

TNR 만료 시 많은 REQUESTED 데이터를 한 번에 release하면 UDP·qdisc·무선 채널에 burst가 몰린다.

CALM의 질문

링크 용량을 사전에 알지 못해도 DDS Writer가 이미 가진 피드백만으로 burst를 스스로 줄일 수 있는가?

03 / WIRELESS BASELINE

CALM 전에 적용한 OPT 1·2

대용량 무선 전송의 IP fragmentation과 느린 손실 피드백을 줄이기 위해 선행 논문의 두 설정을 사용한다. 이들은 CALM의 독창적 기여가 아니라, CALM 제어를 평가하기 위한 공통 전송 기반이다.

Paper-derived
baseline
OPT 1 · RTPS maxMessageSize = 1472 B

RTPS 메시지를 MTU-safe 크기로 제한해 IP 계층의 추가 fragmentation과 한 IP fragment 손실에 따른 전체 datagram 폐기를 줄인다.

OPT 2 · HEARTBEAT period = publish period / 2

대용량 데이터의 누락 발견과 ACKNACK/NACKFRAG 피드백을 앞당긴다. piggyback HEARTBEAT는 기존대로 유지한다.

참고 문서: Optimizing ROS 2 Communication for Wireless Robotic Systems.pdf

04 / CALM CONTROL LOOP

무엇을 관측하고 무엇을 조절하는가

CALM은 wire protocol이나 Reader를 바꾸지 않는다. Writer의 ReaderProxy 상태만 읽고, Reader별 release 스케줄만 바꾸는 폐루프 제어다.

세대관측release 방식핵심 한계 또는 개선
초기 CALM 2.0 그 순간 `REQUESTED`인 byte와 ρ 변화 TNR에서 budget만큼 `REQUESTED→UNSENT`; 잔여분은 다음 feedback에 의존 REQUESTED가 짧은 프로토콜 상태라 지속 부채를 나타내지 못했고, HEARTBEAT 주기 대기로 throughput이 크게 낮아졌다.
기존 CALM 3.0 Reader별 outstanding repair ρ, ACK 정체, N·F oldest-first shared budget, held-new, heartbeat와 독립된 pacing F를 “재전송 영역 중 하나라도 다시 NACK”으로 세어 지속 PER에서 부분 복구도 실패로 오판하고 B·v를 과감쇠했다.
현재 CALM 3.0 ρ·ACK 진행·N에 더해 실제 전송 범위 Qsent와 재요청 범위 Qrepeat 기존 pacing 유지, full-stall만 F로 인정하고 fragment byte 감소를 복구 진행 신호로 사용 `ρ≥2S̄`를 우회하던 Cyclone 예외를 제거해 한 sample 복구에는 불필요하게 개입하지 않는다.
현재 DDS별 기본 동작: CycloneDDS 자동화는 최신 byte-progress/full-stall 판정을 기본으로 사용한다. Fast DDS에는 같은 판정이 구현됐지만 `FASTDDS_CALM_FEEDBACK_BYTE_PROGRESS=1`인 실험 옵션이며, 기본값 OFF에서는 기존의 검증된 absolute-F 안정 프로파일을 유지한다. 따라서 이식은 완료됐지만 정책 parity는 아직 진행 중이다.

ρr

Outstanding repair bytes

Reader가 한 번 이상 NACK한 뒤 아직 ACK로 해소되지 않은 sample/fragment byte의 합. “얼마나 많은 복구 부채가 남았는가”를 나타낸다.

S̄r

평균 serialized sample

ReaderProxy가 현재 관리하는 Change들의 `serializedPayload.length` 평균. 사용자 입력 payload가 아니라 DDS Layer가 동적으로 계산한다.

Ni / Fi

재시도와 확인된 실패

N은 sample i가 실제 repair 전송에 들어간 횟수다. 최신 F는 feedback guard 이후 비교 가능한 실제 전송 범위가 하나도 줄지 않은 full-stall 횟수다.

Qs / Qr

Fragment byte progress

Qsent는 feedback bitmap 범위에서 실제 재전송한 byte, Qrepeat는 그중 다시 요청된 byte다. 둘의 차이를 ACK 이전의 보조 복구 신호로 사용한다.

μ̂DDS

DDS-visible service rate

cumulative ACK로 새로 확인된 byte와 관측 창으로 추정한다. iperf, RSSI, NIC·qdisc 통계 없이 v의 범위를 Reader별로 자율 설정한다.

B / v / TP

제어 출력

B는 tick당 새 전송+재전송 총 release window, v는 평균 release rate, TP는 다음 batch까지의 pacing 간격이다.

OBSERVATION S̄_r = Σ serialized_sample_bytes_i / M_r ρ_r = Σ L_i · 1{sample i was NACKed and is not cumulatively ACKed} FRAGMENT FEEDBACK PROGRESS Q_sent,k = bytes actually retransmitted inside feedback scope k Q_repeat,k = bytes in Q_sent,k requested again by the next NACKFRAG p_k = 1 - Q_repeat,k / Q_sent,k F_i(k+1) = F_i(k) + 1{Q_sent,k > 0 AND Q_repeat,k = Q_sent,k} ACTIVATE ρ_r ≥ 2S̄_r AND (ρ_r non-shrinking for at least 2 valid feedback rounds OR cumulative ACK stall ≥ 500 ms) PACING T_P,k = max(T_P,min, 8B_k / v_k, 1.10T_drain,k) T_P,min = 2 ms SCHEDULING PER TICK b_r = min(oldest_repair_bytes, B_k) b_n = min(held_new_bytes, B_k - b_r) b_r + b_n ≤ B_k EXIT ρ_r = 0 and held-new drained → reset controller → NORMAL
F = 0 · 복구 진행 B와 v를 즉시 줄이지 않음

첫 재전송 또는 Qrepeat<Qsent인 부분 복구는 정상 진행일 수 있으므로 충분한 전송 기회를 준다.

F = 1 · Soft decrease B × 0.80 / v × 0.90

실제 전송 범위가 한 번도 줄지 않은 첫 full-stall을 확인했을 때만 완만하게 줄인다.

F ≥ 2 · Hard decrease B × 0.75 / v × 0.875

같은 sample의 full-stall이 반복되면 burst와 평균 release rate를 함께 낮춘다.

핵심 변경: F는 CALM 진입의 필수 AND 조건이 아니다. ρ와 ACK 진행 정체가 예방적 pacing을 먼저 켜고, F는 실제로 보낸 fragment가 하나도 해소되지 않은 경우에만 감속을 정당화한다. CycloneDDS의 과거 `ρ≥S̄ AND F≥1` 우회 조건은 지속 PER에서 불필요한 개입을 만들었으므로 제거했다.

NORMAL

정상 복구에는 기존 Fast DDS 동작을 유지한다. 첫 NACK만으로 감속하지 않으며, TNR 만료 직전에 복구 부채와 ACK 진행 상태를 평가한다.

CALM_ACTIVE

진입 조건이 만족되면 모든 REQUESTED를 한꺼번에 release하지 않는다. repair를 oldest-first로 pacing하고, 남은 B만 held-new에 배분한다.

PAYLOAD-ADAPTIVE BOUNDS B_min = max(128 KiB, 0.25S̄) B_initial = max(512 KiB, 1.00S̄) B_max = max(2 MiB, 2.00S̄) AI_B = max(256 KiB, 0.25S̄) DDS-ONLY SERVICE ESTIMATOR T_est = max(4T_P,min, 2T_HB, 4RTT_EWMA) g_ack = 8A_window / T_window g_sample = min(g_ack, 1.05max(v_command, g_offered)) μ̂_DDS,k+1 = μ̂_DDS,k + α(g_sample - μ̂_DDS,k) α_up = 0.25, α_down = 0.10 DYNAMIC RELEASE RATE v_live = 8L_atom / max(T_HB, T_guard) v_min = max(v_live, 0.25μ̂_DDS) v_initial = max(v_min, μ_entry) v_max = max(v_initial, 2max(μ̂_DDS, μ_entry)) AI_v = max(v_live, 0.25max(μ̂_DDS, μ_entry)) FAILURE / RECOVERY CONTROL first full-stall F=1: B ← max(B_min, 0.80B), v ← max(v_min, 0.90v) repeated full-stall: B ← max(B_min, 0.75B), v ← max(v_min, 0.875v) ACK success: B ← min(B_max, B + AI_B) v ← min(v_max, v + AI_v) fragment progress: p = 1 - Q_repeat/Q_sent B ← min(B_max, B + p·AI_B) v ← min(v_max, v + p·AI_v)

폐루프 모델과 계수의 해석

아래 식은 구현을 설명하는 단순화 모델이다. 0.80·0.90·0.75·0.875 등의 수치가 수학적으로 유일한 최적이라는 증명은 아니며, 후보 실험에서 선택된 현재의 경험적 안정 영역이다.

BACKLOG DYNAMICS ρ_{k+1} = max(0, ρ_k + a_repair,k - s_ack,k) Δρ_k = ρ_{k+1} - ρ_k desired local stability: E[s_ack,k] > E[a_repair,k] → E[Δρ_k] < 0 → ρ → 0 RELEASE COMMAND r_k = 8B_k / T_P,k because T_P,k ≥ 8B_k/v_k, r_k ≤ v_k ON FAILURE B_{k+1} = γ_B B_k, v_{k+1} = γ_v v_k 0 < γ_B < γ_v < 1 r_{k+1}/r_k ≤ γ_v < 1 if the rate term dominates T_P: T_P,k+1/T_P,k = γ_B/γ_v < 1 Interpretation: 한 tick의 burst B는 더 크게 줄이고 tick은 조금 짧게 하되, 평균 release rate r은 반드시 감소시켜 큰 burst를 작은 batch 여러 개로 바꾼다. ACTIVATION ROBUSTNESS ρ ≥ 2S̄ : 적어도 평균 sample 두 개 규모의 repair debt non-shrinking ≥ 2 : 한 번의 확률적 NACK fluctuation을 congestion으로 오판하지 않음 ACK stall ≥ 500 ms : 10 Hz 기준 약 5 publish intervals 동안 frontier 무진전 EXPECTED LOAD BOUNDARY λ_effective = λ_new,release + r_repair stable region requires λ_effective < μ_service CALM은 μ_service를 직접 알지 않고 μ̂_DDS와 feedback으로 λ_effective를 낮춘다.
수식의 적용 범위: 지속적으로 λ>μ이고 손실도 끝나지 않으면 어떤 완전 신뢰성 제어도 유한한 지연을 보장할 수 없다. 이 영역의 목표는 무조건 ρ=0이 아니라 발산과 불필요한 중복 재전송을 줄이고, 잘못된 CALM 개입으로 Default보다 악화되지 않게 하는 것이다.

제어 경계: CALM은 애플리케이션의 write()를 막거나 오래된 sample을 버리지 않는다. 새 sample은 WHC에 held-new로 유지하고 네트워크 release 시점만 조절한다. OS socket buffer, qdisc, NIC 설정과 사전 링크 대역폭도 제어 입력으로 사용하지 않는다.
기존 FlowController와의 관계: 정적인 bytes-per-period 대역폭 제한은 사용하지 않는다. CALM이 B·v·TP와 release 대상을 결정하고, 기존 FlowController는 DATA/DATA_FRAG 구성, locator 선택, 전송 thread, fragment 순회와 실패 재등록을 수행하는 실행 경로로만 재사용한다.

시간 순서에 따른 실행 과정

CALM의 pacing은 이미 요청된 repair를 처리할 때 다음 3초 HEARTBEAT까지 기다리지 않는다.

06 / EXPECTED IMPACT

제대로 완성했을 때의 기대효과

아래 항목 중 loopback 안정화는 관측됐고, 무선·다중 Reader·벤더 독립성은 향후 검증 대상이다.

재전송 폭풍 억제

큰 REQUESTED 집합을 한 번에 쏟지 않고 B와 TP로 나눠 양성 피드백을 음의 피드백으로 전환한다.

Tail delay 감소

oldest gap을 우선 복구해 ACK base가 다시 전진하도록 만들고, 뒤에 쌓인 in-order delivery 지연을 줄인다.

완전 신뢰성 유지

샘플을 버리는 부분 신뢰성 방식이 아니라 release 시점과 양을 조절한다. 목표는 ρ→0과 2000/2000 완료다.

DDS Layer 자율성

사전 링크 용량, RSSI, 커널 큐 크기를 요구하지 않고 Writer의 NACK·ACK·WHC 상태만 사용한다.

Reader별 격리

나쁜 Reader의 repair debt가 다른 Reader의 budget을 잠식하지 않도록 ReaderProxy별 제어 루프를 둔다.

표준 호환성

RTPS wire format과 애플리케이션 API를 바꾸지 않아 stock Reader와 통신 가능한 Writer-side scheduling으로 유지한다.

07 / ROADMAP

앞으로 구현·최적화할 항목

파라미터 하나의 최저 p95보다, 여러 손실 유형과 무선 조건에서 실패하지 않는 강인한 영역을 찾는 것이 우선이다.

P0 · 무선 검증

실험용 Wi-Fi에서 동일 조건 A/B 반복

Normal·CASE L·CASE D·CASE A에서 Default/CALM을 교차 순서로 각 3~5회 실행하고, 2000/2000·p95·jitter·수신 Hz·ρ·재전송 횟수를 함께 비교한다.

P0 · DDS parity

Fast/Cyclone full-stall 정책 통일

Cyclone 최신 Qsent/Qrepeat 판정을 Fast의 기본 안정 프로파일과 여러 λ≤μ 조건에서 반복 비교한다. Fast 실험 옵션이 명확한 우위를 보일 때만 기본값으로 승격한다.

P1 · 활성 조건 검증

ρ 임계값과 full-stall 조건의 강인한 범위 탐색

`2S̄`, non-shrinking 2 rounds, ACK stall 500 ms와 `Q_repeat=Q_sent`가 payload·Hz·PER 변화에도 유효한지 확인한다. 한 조건 최적값이 아니라 안전 영역을 찾는다.

P1 · pacing

TP 하한과 drain 추정 검증

`max(2 ms, 8×batch/v, drain×1.10)`이 이전 batch 중첩을 실제로 막는지 transport enqueue/complete 시각과 패킷 캡처로 검증한다.

P1 · 스케줄링/QoS

held-new admission과 History 상호작용

최대/최소 admission window 8/2 MiB, KEEP_LAST depth, blocking write, 다수 Writer·Reader에서 oldest-repair 우선 정책의 starvation과 공정성을 확인한다.

P1 · Cyclone 회귀 검증

최신 strict detector로 표준 8조건 재실행

기존 Cyclone 포팅 8조건은 absolute-F 버전 결과다. 최신 full-stall·strict detector로 동일 8조건과 실제 Wi-Fi를 다시 실행해 활성 조건에서의 이득도 확인한다.

P2 · 측정 신뢰도

계측 오버헤드 제거와 통계 설계

고용량 storm CSV를 sampling/비동기 기록으로 바꾸고, confidence interval·효과 크기·실패율을 포함한 재현 가능한 실험 manifest를 만든다.
